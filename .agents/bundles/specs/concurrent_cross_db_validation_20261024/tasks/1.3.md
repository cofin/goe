# Task 1.3: Refactor offload_validation.py, agg_validate.py, and cli/commands/validate.py onto CrossDbValidator

## Objective

1. Replace the 977-LOC implementation in `src/goe/offload/offload_validation.py` with a ~180-LOC orchestrator facade that resolves source and target table metadata, builds aggregate batches via `CrossDbValidationBuilder`, executes them via `CrossDbValidator` from `goe.offload.validation`, and logs results through `OffloadMessages`.
2. Update `src/goe/scripts/agg_validate.py` to delete `REGEX_FILTER` and `parse_python_from_string`, validating `--filters` via `CrossDbValidationBuilder.parse_filter_clause` and supporting opt-in `--diff` row-level primary-key diagnostics via DuckDB 2.0 `EXCEPT`.
3. Update `src/goe/cli/commands/validate.py` to add the opt-in `--diff` flag (`is_flag=True, default=False`) and wire it to `CrossDbValidator` / `run_agg_validate`.
4. Re-export `AggregateQuestion`, `ColumnMismatch`, `CrossDbValidationBuilder`, `CrossDbValidator`, `ValidationBatchQuery`, and `ValidationResult` in `src/goe/offload/validation/__init__.py` (or directly in `offload_validation.py` so existing offload callers stay compatible).

## Context

- `src/goe/offload/offload_validation.py:1-977` currently defines `CrossDbValidator`, `CrossDbValidatorException`, `OffloadValidationException`, `DEFAULT_SELECT_COLS`, `DEFAULT_AGGS`, `GROUPBY_PARTITIONS`, `validate_raw_filter_clause`, and `combine_validation_filters`.
- `src/goe/scripts/agg_validate.py:46, 105-141` uses `REGEX_FILTER` to split `--filters` on commas and whitespace, failing on valid SQL predicates such as `COL IN (1, 2)` or `NAME = 'foo bar'`.
- `src/goe/cli/commands/validate.py:28-108` defines the `goe validate` CLI command.
- Note on file ownership: `src/goe/offload/validation/__init__.py` was created in Task 1.1; do not touch `src/goe/offload/validation/__init__.py`, `ast_builder.py`, or `runner.py` in this task. Keep all edits in `src/goe/offload/offload_validation.py`, `src/goe/scripts/agg_validate.py`, `src/goe/cli/commands/validate.py`, and `tests/unit/offload/test_offload_validation.py`.

## Steps

- [ ] 1. Run `uv run pytest tests/unit/offload/test_offload_validation.py -v` to record the existing baseline before refactoring.
- [ ] 2. Extend `tests/unit/offload/test_offload_validation.py` with tests covering:
  - `test_offload_validation_delegates_to_cross_db_validator`: construct `CrossDbValidator` via `goe.offload.offload_validation` with mocked frontend/backend adapters, run `.validate(execute=True)`, and verify it delegates batch construction to `CrossDbValidationBuilder` and execution to `goe.offload.validation.runner.CrossDbValidator`.
  - `test_agg_validate_post_process_args_accepts_complex_sql_filters`: call `post_process_args` on `AggValidateOptions` with `filters="PROD_ID IN (10, 20) AND NOTE = 'a \"quoted\" string'"` and verify it validates cleanly via `CrossDbValidationBuilder.parse_filter_clause` without `REGEX_FILTER` errors.
  - `test_validate_cli_diff_flag_opt_in_only`: invoke `validate` via `click.testing.CliRunner` with and without `--diff`, asserting `diff=False` by default and `diff=True` when `--diff` is passed.
- [ ] 3. Refactor `src/goe/offload/offload_validation.py` down to ~180 LOC:
  - Delete `ValidationSqlEngine`, `front_and_back_match`, `merge_front_end_results`, `isclose(float(front), float(back))`, and `ParallelExecutor` usage.
  - Delegate filter validation in `validate_raw_filter_clause` and `combine_validation_filters` to `CrossDbValidationBuilder.parse_filter_clause`.
  - Delegate query generation and concurrent execution in `CrossDbValidator.validate` to `goe.offload.validation.ast_builder.CrossDbValidationBuilder` and `goe.offload.validation.runner.CrossDbValidator`, returning `(result.passed, result)`.
- [ ] 4. Refactor `src/goe/scripts/agg_validate.py`:
  - Delete `REGEX_FILTER` (`:46`) and `parse_python_from_string` import (`:36`).
  - In `post_process_args`, validate `args.filters` through ` validate_raw_filter_clause` (`CrossDbValidationBuilder.parse_filter_clause`) instead of splitting on commas with `REGEX_FILTER`.
  - When `getattr(args, "diff", False)` is `True` and validation detects a mismatch, invoke `validator.run_row_diff()` (using DuckDB 2.0 `EXCEPT` over source and target key/hash projections) to log mismatched primary keys.
- [ ] 5. Update `src/goe/cli/commands/validate.py` to add `@click.option("--diff", is_flag=True, default=False, help="Run opt-in DuckDB row-level diff when aggregate validation fails.")`.
- [ ] 6. Run the verification block and confirm all unit tests, formatting, linting, type checks, and architecture checks pass.
