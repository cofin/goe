# Task 1.3: Port upstream `#278` `ExecutionId.from_uuid` validation

## Objective

Make `ExecutionId(from_uuid=...)` / `ExecutionId.from_uuid(...)` reject non-`uuid.UUID` values exactly as upstream `gluent/goe#278` does, and port its regression tests.

## Context

- Baseline commit `46890a8`; no earlier task edits these files.
- `src/goe/orchestration/execution_id.py:36-37` stores the value unchecked:
  ```python
          elif "from_uuid" in kwargs:
              self.id = kwargs["from_uuid"]
  ```
  `_str_as_uuid` ends at line 61, `_new_id` is at 63-65, and `from_uuid` is at 75-77:
  ```python
      @staticmethod
      def from_uuid(b: uuid.UUID):
          return ExecutionId(from_uuid=b)
  ```
- Upstream (<https://github.com/gluent/goe/commit/dee61e8>, `src/goe/orchestration/execution_id.py`) adds `_uuid_as_uuid(u)` (returns `None` for `None`, otherwise `assert isinstance(u, uuid.UUID)`), calls it from `__init__`, and renames the `from_uuid` parameter to `u`. Its test change in `tests/unit/persistence/test_orchestration_repo_client.py` appends `i2 = ExecutionId.from_uuid(i.id)` / `self.assertEqual(i, i2)` to `test_orchestration_execution_id` and adds `test_orchestration_execution_id_from_uuid_invalid`.
- `tests/unit/persistence/test_orchestration_repo_client.py:25-37` is `test_orchestration_execution_id` (last statement `self.assertEqual(i, i2)` at 37); line 38 is blank and `test_type_safe_json_dumps` starts at 39. Imports already include `uuid`, `TestCase`, and `ExecutionId`.
- No caller passes `from_uuid` today (`git grep -n from_uuid -- src tests` lists only `execution_id.py`).
- `requires-python = ">=3.12"`: do not add annotations that reference `ExecutionId` inside its own class body unquoted.
- Strategy justification: accepting arbitrary objects as an execution id is a defect fixed upstream → `regression_tdd`.
