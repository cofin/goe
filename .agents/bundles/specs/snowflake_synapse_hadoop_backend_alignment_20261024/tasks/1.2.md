# Task 1.2: Align Synapse backend API and table onto SQLSpec MSSQL adapter, capabilities, cached catalog, DialectSqlEngine, and TypeMappingRegistry

## Objective

1. Refactor `src/goe/offload/microsoft/synapse_backend_api.py` (`BackendSynapseApi`) to manage database connections and queries through `sqlspec.adapters.mssql` (`MssqlPythonConfig` / `mssql-python`) instead of raw `pyodbc`, expose `SYNAPSE_CAPABILITIES: BackendCapabilities`, cache metadata in `CachedBackendCatalog`, build T-SQL through `DialectSqlEngine("tsql")`, and map columns through `TypeMappingRegistry.for_backend("synapse")`.
2. Refactor `src/goe/offload/microsoft/synapse_backend_table.py` (`BackendSynapseTable`) onto `ColumnSpec`, `TypeMappingRegistry`, `DialectSqlEngine("tsql")`, `CachedBackendCatalog`, and `StagedLoadInsertStrategy`, removing all references to `SynapseColumn`, `synapse_predicate`, and deleted staging column classes.
3. Prove Synapse connection configuration via `MssqlPythonConfig` (SQL authentication, Entra ID Service Principal, and Managed Identity), catalog caching and invalidation, `HASH` / `ROUND_ROBIN` table creation, PolyBase / `COPY INTO` staged ingestion via `StagedLoadInsertStrategy`, and statistics computation in `tests/unit/offload/microsoft/test_synapse_backend.py`.

## Context

- At HEAD `d6a02fe`, `src/goe/offload/microsoft/synapse_backend_api.py:17` imports `pyodbc` directly, manually packs `SQL_COPT_SS_ACCESS_TOKEN` structs (`:10, 250-340`), and formats T-SQL queries by string concatenation. `sqlspec==0.68.0` provides `sqlspec.adapters.mssql` (`MssqlPythonConfig`, `MssqlSyncDriver` backed by `mssql-python`) with native `?` parameter binding, connection pooling, and Entra ID authentication support (already adopted for the MSSQL frontend in Chapter 6.4).
- `src/goe/offload/microsoft/synapse_backend_api.py:66-114` imports `SynapseColumn`, `SynapseLiteral`, `SYNAPSE_BACKEND_CAPABILITIES`, and `parse_stats_into_tab_col` / `transform_stats_as_tuples` from `goe.util.hive_table_stats` (relocated to `goe.backend.hadoop` in Chapter 5.1).
- `src/goe/offload/microsoft/synapse_backend_table.py:19-45` imports `synapse_predicate`, `SynapseColumn`, `avro_staging_file` constants, and `parquet_column` constants. Chapters 7.1, 8.2, and 9.1 replace those with `DialectSqlEngine("tsql")`, `ColumnSpec`, and `TypeMappingRegistry.for_backend("synapse")`.
- Synapse capabilities preserved at HEAD (`SYNAPSE_BACKEND_CAPABILITIES`): `[schema].[table]` bracketed or double-quoted identifiers, distribution (`DISTRIBUTION = HASH([col])` when `bucket_hash_col` is set, else `ROUND_ROBIN`), single-column range partitioning (`PARTITION ([col] RANGE RIGHT FOR VALUES (...))`), `CLUSTERED COLUMNSTORE INDEX` / `HEAP`, PolyBase external tables (`CREATE EXTERNAL TABLE ... WITH (LOCATION = ..., DATA_SOURCE = ..., FILE_FORMAT = ...)`), `COPY INTO` loads, and per-column statistics creation/update (`CREATE STATISTICS` / `UPDATE STATISTICS`).
