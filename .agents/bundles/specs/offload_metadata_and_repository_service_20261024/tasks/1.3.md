# Task 1.3: Migrate orchestration, offload, sync, report, and Listener callers to OffloadMetadata and OracleRepositoryService

## Objective

1. Update `src/goe/offload/registry.py` so `AdapterRegistry` resolves `OracleRepositoryService` for `DBTYPE_ORACLE` repository clients.
2. Migrate `src/goe/offload/offload_metadata_functions.py`, `src/goe/orchestration/orchestration_runner.py`, `src/goe/orchestration/operation.py`, and `src/goe/listener/services/system.py` (plus any remaining imports in `src/goe/`) from `OrchestrationMetadata` and `OrchestrationRepoClientInterface` to `OffloadMetadata` and `OracleRepositoryService`.
3. Delete `src/goe/persistence/orchestration_metadata.py` and update `tests/unit/offload/test_offload_metadata.py` and `tests/unit/listener/test_system_service.py`.

## Context

- `src/goe/offload/offload_metadata_functions.py:24-29` imports `OrchestrationMetadata` and constants from `goe.persistence.orchestration_metadata`. `gen_offload_metadata` (`:56-141`) returns `OrchestrationMetadata.from_attributes(...)`, and `gen_and_save_offload_metadata` (`:144-180`) calls `goe_metadata.save()` inside `messages.offload_step(command_steps.STEP_SAVE_METADATA, ...)`. With `OffloadMetadata(FrozenBaseStruct)`, `gen_and_save_offload_metadata` calls `repo_client.set_offload_metadata(goe_metadata)` inside `messages.offload_step`.
- `decode_metadata_incremental_high_values_from_metadata` (`src/goe/offload/offload_metadata_functions.py:277-295`) asserts `isinstance(base_metadata, OffloadMetadata)`.
- `src/goe/orchestration/operation.py` and `src/goe/orchestration/orchestration_runner.py` instantiate the repository client and read or persist `OffloadMetadata`. Notice defect 12 in `src/goe/orchestration/operation.py:1194`: `get_hybrid_metadata(offload_options)` passes `offload_options` into `force: bool`; ensure `get_hybrid_metadata` accepts `force: bool = False` and queries `repo_client.get_offload_metadata(owner, table_name)`.
- `src/goe/listener/services/system.py:15-21, 40-46` imports `orchestration_repo_client_factory` and `OrchestrationRepoClientInterface`. After Chapter 5.1 introduced `AdapterRegistry` in `src/goe/offload/registry.py`, `SystemService.get_repo` resolves `OracleRepositoryService` via `AdapterRegistry`.
