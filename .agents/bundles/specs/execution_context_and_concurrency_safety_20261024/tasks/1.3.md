# Task 1.3: Route orchestration logging through the execution context and fix execution-state defects

## Objective

1. `logging_init` keeps every public function name and signature but stores no module-level mutable state: it reads and rebinds the current `ExecutionContext`.
2. `OffloadMessages` emits every log line, warning, step start, step end, and skipped step through its own `ExecutionContext` (built from its constructor arguments or passed in), keeping byte-identical output and repository step arguments.
3. `offload_table` raises for unsupported targets, stops writing `logging_init.suppress_stdout_override`, and stops mutating the settings object; `get_offload_target_table` and `offload_table` both use a derived execution-scoped settings copy.
4. Regression tests prove: concurrent commands write to their own log files; a Listener-style command with `suppress_stdout` prints nothing from `logging_init.log`; unsupported targets raise; the caller's settings object is unchanged after an offload.
