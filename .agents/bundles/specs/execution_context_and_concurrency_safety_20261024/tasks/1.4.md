# Task 1.4: Make OrchestrationRunner stateless and fix operation defects

## Objective

1. Remove all per-command mutable instance attributes (`_execution_id`, `_messages`, `_max_hybrid_name_length`) and the throwaway frontend connection helper `_get_max_hybrid_identifier_length` from `OrchestrationRunner` (`src/goe/orchestration/orchestration_runner.py`), accept prebuilt `settings` and extra `sinks: Sequence[ExecutionSink] = ()`, and bind a fresh `ExecutionContext` per command execution.
2. Fix three execution-path defects in `src/goe/orchestration/operation.py`: guard process-wide `NLS_LANG` resolution and assignment under a module-level `threading.Lock` so it runs at most once per process, fix `validate_sort_columns` to set `created_api = True` when constructing a backend API and call `self.get_hybrid_metadata()` with no arguments, and delete the unused `max_hybrid_name_length` parameter and attribute.
3. Update `src/goe/orchestration/cli_entry_points.py` (`offload_by_cli`) to pass the already-constructed settings object into `OrchestrationRunner(settings=config)` instead of building settings twice.
4. Remove the module-global `_runner` singleton and `LazyOrchestrationRunner` proxy from `src/goe/listener/services/orchestrate.py` and construct a fresh `OrchestrationRunner` per job in `src/goe/listener/jobs.py`.

## Context

- `src/goe/orchestration/orchestration_runner.py:64-69` stores `self._execution_id`, `self._messages`, and `self._max_hybrid_name_length` on the runner instance and mutates them inside `_init_command` (`:350-352`). When two Listener jobs execute concurrently against a shared runner, the second job overwrites `_execution_id` and `_messages` mid-flight.
- `src/goe/orchestration/orchestration_runner.py:320-336` defines `_get_max_hybrid_identifier_length(self, dry_run: bool) -> int`, which opens and closes a frontend connection solely to read `frontend_api.max_table_name_length()` and pass `max_hybrid_name_length` into `OffloadOperation.from_dict` / `OffloadOperation.from_options` (`:284-305`). In `src/goe/orchestration/operation.py:658, 664`, `self.max_hybrid_name_length = max_hybrid_name_length` is written and never read anywhere in `src/goe/`.
- `src/goe/orchestration/operation.py:170-197` (`nls_lang_exists`, `nls_lang_has_charset`, `set_nls_lang_default`, `check_and_set_nls_lang`) checks and mutates `os.environ["NLS_LANG"]` without synchronization. Concurrent worker threads seeing `NLS_LANG` unset both query `get_db_charset(opts)` and race on `os.environ["NLS_LANG"]`.
- `src/goe/orchestration/operation.py:1173-1206` (`validate_sort_columns`):
  - Line `1173` initializes `created_api = False`, and line `1181` inside `if backend_api is None:` sets `created_api = False` again instead of `True`, so the `finally` block at `:1204-1206` (`if created_api: backend_api.close()`) never closes the newly created `BackendApi`.
  - Line `1194` calls `self.get_hybrid_metadata(offload_options)`, passing `offload_options` into `get_hybrid_metadata(self, force=False)` (`:787-797`), where a truthy `offload_options` object forces an uncached repository metadata lookup on every call instead of using `self._existing_metadata`.
- `src/goe/orchestration/cli_entry_points.py:47-59` (`offload_by_cli`) constructs `config = OrchestrationConfig.from_dict(config_overrides)` (or the `GOESettings` equivalent from Chapter 5.3) at line `53` to call `config.log_connectivity_messages(...)`, and then calls `OrchestrationRunner(config_overrides=config_overrides)` at line `57`, which calls `_gen_config` (`orchestration_runner.py:263-267`) and constructs a second settings instance.
- `src/goe/listener/services/orchestrate.py:13-31` defines module-global `_runner: OrchestrationRunner | None = None`, `get_orchestration_runner()`, `LazyOrchestrationRunner`, and `orchestration_runner = LazyOrchestrationRunner()`. `src/goe/listener/jobs.py:12, 17-22` imports `orchestration_runner` and runs `await async_(orchestration_runner.offload)(params=params, execution_id=execution_identifier)`. Note that the Master PRD 10 roadmap table refers to `src/goe/listener/services/orchestration.py`, whereas the path in the repository at HEAD `d6a02fe` is `src/goe/listener/services/orchestrate.py`.
- Task 1.2 and Task 1.3 delivered `ExecutionContext`, `bind_execution_context`, `current_execution_context` (`src/goe/orchestration/context.py`), `ExecutionSink` (`src/goe/orchestration/sinks.py`), and `OffloadMessages.from_context` / `messages.context` (`src/goe/offload/offload_messages.py`).
