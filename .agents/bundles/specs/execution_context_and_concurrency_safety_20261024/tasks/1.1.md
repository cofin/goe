# Task 1.1: Pin byte-exact console and log output

## Objective

1. Record the exact stdout bytes and log-file bytes that `OffloadMessages` and `goe.orchestration.logging_init` produce today for every verbosity level, ANSI on and off, warnings, notices, step success, skipped steps, optional-step failures, forced step exceptions, the step-delta summary, and the message summary.
2. Record the exact repository step calls (`start_command_step`, `end_command_step`) that `offload_step` makes for a repository-logged command type.
3. Keep these tests green and unchanged through Tasks 1.2–1.4; they are the byte-identical contract required by the roadmap (§3 constraint 6).

## Context

- `src/goe/offload/offload_messages.py:202-225` (`log`): file line first (`(line or "") + "\n"` then `flush()`), then stdout: `QUIET` prints `"."`; otherwise prints when `detail is None or detail <= self._detail` and `self._detail != SUPPRESS_STDOUT`, wrapped by `ansi_wrap` (`:174-182`, `COLORS` at `:43-63`).
- `:239-248`: `notice` appends to `messages["notices"]` once and logs at `VERBOSE` by default; `warning` appends once, logs `"WARNING:" + msg`, then calls `add_span_log_event("WARNING", msg)`.
- `:270-399` (`offload_step`): logs `""`, the step title with `ansi_code="underline"`, and (when `execute=True`) a `%c` timestamp at `VERBOSE` with `ansi_code="grey"`; skipped steps log `"skipped"`; success logs `"Step time: <delta>"` at `VERBOSE` and `"Done"` with `ansi_code="green"` (execute only); optional failures log the traceback at `VVERBOSE`, a red `WARNING:Error in "<title>": <exc>` and a green `"Optional step, continuing"`; `error_before_step` / `error_after_step` raise `OffloadMessagesForcedException("Forcing exception before step: <title>")` / `"... after step: <title>"`.
- Repository calls (`:322-390`) happen only when the parent command type is not one of `COMMAND_DIAGNOSE`, `COMMAND_OSR`, `COMMAND_SCHEMA_SYNC`, `COMMAND_TEST` (`orchestration_constants`): `start_command_step(execution_id, command_type, step_constant)`; success `end_command_step(csid, "SUCCESS")` when there are no trace ids, else `end_command_step(csid, "SUCCESS", step_details=trace_ids)`; failure `end_command_step(csid, "ERROR", step_details={CTX_ERROR_MESSAGE: str(exc), CTX_EXCEPTION_STACK: <traceback>, **trace_ids})`. Without OpenTelemetry configured, `current_trace_ids()` returns an empty mapping.
- `:466-492` (`log_step_deltas`): header `"{0: <W} {1: >9} {2: >7}".format("Step", "Seconds", "Percent")` and rows sorted by seconds descending, all at `VVERBOSE`, followed by `"Total time logged: <timedelta>"`.
- `src/goe/orchestration/logging_init.py:28-54` (`log`): with no `options` set, writes the line to `sys.stderr` and prints it unwrapped to stdout; with options, `quiet` prints `"."`, otherwise prints ANSI-wrapped lines for `detail == normal`, or `detail <= verbose and options.verbose`, or `detail <= vverbose and options.vverbose`. `init()` (`:139-145`), `init_log()` (`:114-131`, file name from `standard_log_name`, which embeds a timestamp), `log_timestamp()` (`:72-76`), `log_command_line()` (`:61-64`), `get_log_fh_name()` (`:134-136`), `log_close()` (`:67-69`).
- Do not characterize `suppress_stdout` behavior of `logging_init.log`: Task 1.3 deliberately changes it (the Listener must not print), and pins the new behavior with a regression test.
- Byte comparisons must not depend on wall-clock values. Normalize with exactly these substitutions before comparing:
  - `re.sub(r"Step time: \d+:\d{2}:\d{2}", "Step time: <DELTA>", text)`
  - `re.sub(r"^\w{3} \w{3} [ \d]\d \d{2}:\d{2}:\d{2} \d{4}$", "<TIMESTAMP>", text, flags=re.MULTILINE)` (the `%c` format in the C locale)
- Chapter 5.4 relocates `standard_log_name` out of `src/goe/util/misc_functions.py` and moves `GOELogFileHandle` onto `google.cloud.storage.Blob.open`; local paths still open regular files. Find the current homes with `git grep -n "def standard_log_name\|class GOELogFileHandle" src/goe`. Tests below only use public functions and a local temporary directory, so they do not import those helpers directly except `GOELogFileHandle` for opening a log file handle.
