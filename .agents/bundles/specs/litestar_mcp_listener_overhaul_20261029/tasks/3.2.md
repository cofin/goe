## Objective

Complete GOE schema evolution and data validation parity in the Listener by hydrating live frontend/backend catalog snapshots inside `SystemService.preview_schema_drift`, adding `POST /api/orchestration/sync/` (`apply_schema_sync`) backed by `SchemaSyncService` under `orchestration_lock_for_table` with `ListenerCache` invalidation and MCP-only MRTR/`confirmation_token` gating, and adding read-only `POST /api/orchestration/validate/` (`validate_table`) backed by `CrossDbValidator` and `CrossDbValidationBuilder`.

## Context

- `SystemService.preview_schema_drift` (`src/goe/listener/services/system.py`) currently defaults `source_columns=()` and `target_columns=()`, returning an empty diff when called from `TablesController` unless unit tests supply synthetic column tuples. Hydrating `source_columns` via `self.get_table_columns(schema_name, table_name)` and `target_columns` via `self.get_repo(self.config, self.messages).get_offload_metadata(schema_name.upper(), table_name.upper())` + `create_backend_table(..., dry_run=True).get_columns()` makes live drift detection work out of the box.
- `OrchestrationRunner.schema_sync` (`src/goe/orchestration/orchestration_runner.py`) is retired and raises `OrchestrationRunnerException("Schema Sync no longer exists")`; schema evolution is owned directly by `SchemaSyncService` (`src/goe/sync/differ.py`).
- Direct HTTP REST callers (`get_mcp_request_context()` raising `RuntimeError`) receive `SchemaSyncExecutionResult` directly from `POST /api/orchestration/sync/` without confirmation tokens or `MCPToolResult` wrappers, while `/mcp` callers (`task_input_before_start=True`, `task_support="optional"`) must satisfy `ConfirmationGate.require_mcp_confirmation(...)` when `execute=True`.
- `CrossDbValidator` (`src/goe/offload/offload_validation.py`) exposes `validate(...) -> tuple[bool, str]` for read-only aggregate verification (`COUNT`, `MIN`, `MAX`, `SUM`, `AVG`, `STDDEV`) and `run_row_diff() -> list[dict[str, Any]]` for DuckDB `EXCEPT` row-level diffing, while `CrossDbValidationBuilder("oracle").parse_filter_tuples(request.filters)` validates filter clauses before query generation.
- Strategy justification (`behavior_tdd`): live catalog drift hydration, table-locked schema evolution with MCP confirmation and cache invalidation, and cross-DB validation endpoints are new observable behaviors verified red-first in canonical `tests/unit/listener/{test_operations_service,test_system_service,test_orchestration_controllers}.py`.

## Steps

1. Add failing behavioral tests in `tests/unit/listener/test_system_service.py`, `tests/unit/listener/test_operations_service.py`, and `tests/unit/listener/test_orchestration_controllers.py` covering:
   - `SystemService.preview_schema_drift` automatically hydrates `SourceColumnSnapshot` and `TargetColumnSnapshot` via `get_table_columns` and `self.get_repo(self.config, self.messages).get_offload_metadata(...)` + `create_backend_table(..., dry_run=True).get_columns()` when explicit column tuples are omitted, and attaches a `ConfirmationChallenge` bound to `apply_schema_sync` (`execute=True`) when `ddl_statements` is non-empty.
   - `POST /api/orchestration/sync/` (`apply_schema_sync`):
     - Direct HTTP REST `POST` (`get_mcp_request_context()` raising `RuntimeError`) executes `synchronize_schema` and returns `SchemaSyncExecutionResult` directly without requiring a confirmation token.
     - MCP `tools/call` (`task_input_before_start=True`) with `execute=True` and no confirmation returns `MCPInputRequiredResult` synchronously before creating a `TaskRecord`; succeeds on Round 2 (`requestState` + `inputResponses={"confirm": True}`) or when given the preview-issued `confirmation_token`.
     - Acquires `orchestration_lock_for_table`, executes generated `ALTER TABLE` statements when `execute=True` (or previews without executing when `execute=False`), and invalidates `tables:{SCHEMA}:{TABLE}:*` and `schemas:{SCHEMA}:tables` in `ListenerCache`.
   - `POST /api/orchestration/validate/` (`validate_table`):
     - Runs read-only `CrossDbValidator.validate(...) -> tuple[bool, str]` (and `validator.run_row_diff()` when `not passed and request.include_row_diff and request.execute`) without MRTR confirmation, returning `ValidationResultSummary` (`owner_table`, `passed`, `execute`, `aggregate_functions`, `safe_boundary_applied`, `summary_message`, `differing_rows`).
     - Rejects malformed filter clauses in `CrossDbValidationBuilder("oracle").parse_filter_tuples(request.filters)` with HTTP `400` (`isError: True` in MCP `tools/call`).
2. Add typed request/response DTOs in `src/goe/listener/schemas.py`:
   - Extend `SchemaDriftPreview` with `confirmation_challenge: ConfirmationChallenge | None = None`.
   - `SchemaSyncRequest(FrozenBaseStruct, frozen=True)`: `owner_table: str`, `execute: bool = False`, `confirmation_token: str | None = None`.
   - `SchemaSyncExecutionResult(FrozenBaseStruct, frozen=True)`: `owner_table: str`, `backend: str`, `has_drift: bool`, `applied: bool`, `added_columns: list[str]`, `widened_columns: list[str]`, `ddl_statements: list[str]`, `warnings: list[str]`.
   - `ValidateTableRequest(FrozenBaseStruct, frozen=True)`: `owner_table: str`, `execute: bool = True`, `aggregate_functions: list[str] | None = None`, `select_columns: list[str] | int | None = None`, `filters: str | None = None`, `group_bys: list[str] | None = None`, `skip_boundary_check: bool = False`, `as_of_scn: int | None = None`, `frontend_parallelism: int | None = None`, `include_row_diff: bool = False`.
   - `ValidationResultSummary(FrozenBaseStruct, frozen=True)`: `owner_table: str`, `passed: bool`, `execute: bool`, `aggregate_functions: list[str]`, `safe_boundary_applied: bool`, `summary_message: str`, `differing_rows: list[dict[str, Any]] = msgspec.field(default_factory=list)`.
3. Update `SystemService.preview_schema_drift` (`src/goe/listener/services/system.py`) and `TablesController.preview_schema_drift`:
   - Hydrate source columns via `self.get_table_columns(schema_name, table_name)` and target columns via `self.get_repo(self.config, self.messages).get_offload_metadata(...)` + `create_backend_table(..., dry_run=True).get_columns()` when `source_columns is None` and `target_columns is None` and `self.config is not None`.
   - Attach `ConfirmationChallenge` (`tool_name="apply_schema_sync"`) when additive `ddl_statements` are produced and a `ConfirmationGate` is supplied.
4. Implement `synchronize_schema` and `validate_table` on `ListenerOperationsService` (`src/goe/listener/services/operations.py`) and mount `POST /api/orchestration/sync/` (`@mcp_tool(name="apply_schema_sync", annotations=DESTRUCTIVE_TOOL_ANNOTATIONS, task_support="optional", task_input_before_start=True, ...)`, retaining return annotation `-> schemas.SchemaSyncExecutionResult` with `typing.cast("schemas.SchemaSyncExecutionResult", ...)` on the MCP-only `MCPInputRequiredResult | MCPToolResult` return branch and zero inline `#` comments so `/schema/openapi.json`, `mypy`, and `@mcp_tool` `outputSchema` stay bound to `SchemaSyncExecutionResult`) and `POST /api/orchestration/validate/` (`@mcp_tool(name="validate_table", annotations=READ_ONLY_TOOL_ANNOTATIONS, task_support="optional", ...)`) on `OrchestrationController` (`src/goe/listener/controllers/orchestration.py`).
