## Objective

Implement end-to-end cooperative job cancellation across the durable `GOE_LISTENER_JOBS` queue (`SqliteJobStore`, `OracleJobStore`, `DurableJobWorker`, and `POST /api/orchestration/executions/{execution_id}/cancel/` / `cancel_offload_job`) with worker-thread `ExecutionSink` unwinding so `orchestration_lock_for_table` (`filelock`) is released before `mark_cancelled`, and enable `MCPTaskConfig` (`io.modelcontextprotocol/tasks`: `tasks/get`, `tasks/result`, `tasks/list`, `tasks/cancel`) with `task_support="optional"` on long-running orchestration tools.

## Context

- `GOE_LISTENER_JOBS` (`src/goe/listener/jobs/sql/job_queue.sql` and `src/goe/persistence/oracle/ddl/sql/create_offload_repo_24.sql`) defines `JobState` (`PENDING`, `CLAIMED`, `RUNNING`, `SUCCEEDED`, `FAILED`, `CANCELLED`, `DEAD_LETTER`), yet no `CANCEL_REQUESTED` column, `cancel_job` store method, worker cancellation check, or `/cancel/` endpoint exists in source code.
- Two subtle concurrency invariants in `src/goe/listener/jobs/{store,worker}.py` must hold:
  1. `oracle_claim_pending_jobs` / `sqlite_claim_pending_jobs` and `oracle_reap_expired_to_pending` / `sqlite_reap_expired_to_pending` must filter `CANCEL_REQUESTED = 0`, and `reap_expired_leases` must additionally run `oracle_reap_expired_to_cancelled` / `sqlite_reap_expired_to_cancelled` so expired `CLAIMED`/`RUNNING` rows with `CANCEL_REQUESTED = 1` transition directly to `CANCELLED` instead of resurrecting to `PENDING`.
  2. `default_job_executor` executes synchronous `OrchestrationRunner` inside `asyncio.to_thread` while holding `orchestration_lock_for_table` (`filelock`). Cancelling an outer `asyncio.Task` alone would leave the OS worker thread running and holding `filelock` while releasing `GOE_LISTENER_JOBS_ACTIVE_TBL_UQ` prematurely. Attaching a `_CooperativeCancelSink(ExecutionSink)` (checking a `threading.Event` tripped by `_lease_renewal_loop` when `cancel_requested == True`) raises `JobCancelledError` on the next `ExecutionEvent` inside the worker thread, unwinding `orchestration_lock_for_table` cleanly before `DurableJobWorker` awaits thread exit and calls `self._store.mark_cancelled(...)`.
- Scope separation between cancellation surfaces: `cancel_offload_job` (`POST /api/orchestration/executions/{execution_id}/cancel/`) cancels durable `GOE_LISTENER_JOBS` rows (`execute_offload`), whereas MCP JSON-RPC `tasks/cancel` cancels in-flight `MCPTaskStore` tool runners (`validate_table`, `apply_schema_sync`, `generate_status_report`).
- Strategy justification (`behavior_tdd`): immediate cancellation of `PENDING`/`CLAIMED` jobs, expired-lease cancellation reaping, cooperative `ExecutionSink` worker-thread unwinding before `mark_cancelled`, idempotent terminal job handling, and `tasks/*` JSON-RPC operations are observable state-machine behaviors verified red-first in canonical `tests/unit/listener/{test_job_models,test_job_store_and_worker,test_mcp}.py`.

## Steps

1. Add failing behavioral tests in `tests/unit/listener/test_job_models.py`, `tests/unit/listener/test_job_store_and_worker.py`, and `tests/unit/listener/test_mcp.py` covering:
   - `cancel_job` on a `PENDING` or `CLAIMED` job immediately transitions `status` to `JobState.CANCELLED`, sets `cancel_requested=True` and `finished_at`, clears `lease_expires_at`, prevents `claim_pending_jobs` from claiming cancelled rows, and releases the active-table unique index immediately.
   - `reap_expired_leases` transitions expired `CLAIMED`/`RUNNING` rows with `cancel_requested=True` directly to `JobState.CANCELLED` rather than re-queueing them to `PENDING`.
   - `cancel_job` on a `RUNNING` job sets `cancel_requested=True` while preserving `status == JobState.RUNNING`; on the next lease check in `DurableJobWorker`, the `threading.Event` trips `_CooperativeCancelSink` inside the worker thread (`JobCancelledError`), unwinding the worker thread (and releasing `filelock`) BEFORE `mark_cancelled` transitions the record to `JobState.CANCELLED` without retrying or dead-lettering.
   - `cancel_job` on an already terminal job (`SUCCEEDED`, `FAILED`, `CANCELLED`, `DEAD_LETTER`) returns the unchanged `JobRecord` idempotently; unknown `execution_id` returns `None` (`404` on REST/MCP).
   - `SqliteJobStore._initialize_schema` upgrades pre-existing SQLite tables lacking `cancel_requested` idempotently.
   - `server/discover` advertises `"io.modelcontextprotocol/tasks"` under `capabilities.extensions`, long-running orchestration tools declare `execution.taskSupport == "optional"`, and `tasks/list`, `tasks/get`, and `tasks/cancel` succeed over `POST /mcp`.
2. Update DDL and job queue models/stores:
   - Add `cancel_requested: bool = False` and `JobCancelledError(Exception)` in `src/goe/listener/jobs/models.py`, plus `cancel_requested: bool = False` on `JobStatusResponse` (`src/goe/listener/schemas.py`).
   - Add `CANCEL_REQUESTED NUMBER(1) DEFAULT 0 NOT NULL` / `cancel_requested INTEGER NOT NULL DEFAULT 0` to `src/goe/listener/jobs/sql/job_queue.sql` and `src/goe/persistence/oracle/ddl/sql/create_offload_repo_24.sql`, filter `CANCEL_REQUESTED = 0` (`cancel_requested = 0`) in `oracle_claim_pending_jobs`, `sqlite_claim_pending_jobs`, `oracle_reap_expired_to_pending`, and `sqlite_reap_expired_to_pending`, and add named SQL queries for `*_reap_expired_to_cancelled`, `*_cancel_pending_or_claimed_job`, `*_request_cancel_running_job`, and `*_mark_cancelled`.
   - Implement `cancel_job(*, execution_id: str, reason: str | None = None, now: datetime | None = None) -> JobRecord | None` and `mark_cancelled(*, job_id: str, worker_id: str, reason: str | None = None, now: datetime | None = None) -> bool` on `JobStoreProtocol`, `SqliteJobStore` (including idempotent `PRAGMA table_info(goe_listener_jobs)` + `ALTER TABLE goe_listener_jobs ADD COLUMN cancel_requested INTEGER NOT NULL DEFAULT 0`), and `OracleJobStore`, update `_row_to_job_record` in `src/goe/listener/jobs/store.py` to unpack the strict 16-column `GOE_LISTENER_JOBS` projection (with zero `len(row)` compatibility fallback), and update `_FakeOracleCursor` synthetic row tuples in `tests/unit/listener/test_job_store_and_worker.py` from 15 to 16 columns.
3. Update `DurableJobWorker` (`src/goe/listener/jobs/worker.py`):
   - Pass a per-job `cancel_event: threading.Event` (via `_CooperativeCancelSink(ExecutionSink)` in `default_job_executor`, falling back gracefully for custom 1-arg test executors) into the execution path.
   - Have `_lease_renewal_loop` check `get_job_by_execution_id` / lease status and call `cancel_event.set()` when `cancel_requested` is `True`; await worker completion (`JobCancelledError` or `asyncio.CancelledError` for pure async executors) so `orchestration_lock_for_table` unwinds completely BEFORE calling `self._store.mark_cancelled(...)`.
4. Mount `POST /api/orchestration/executions/{execution_id:str}/cancel/` (`@mcp_tool(name="cancel_offload_job", annotations=IDEMPOTENT_MUTATION_ANNOTATIONS, ...)` documenting that it cancels durable `GOE_LISTENER_JOBS` rows while `tasks/cancel` cancels in-flight MCP tool tasks) on `OrchestrationController` (`src/goe/listener/controllers/orchestration.py`), and enable `tasks=MCPTaskConfig(...)` in `build_mcp_config()` (`src/goe/listener/mcp.py`).
