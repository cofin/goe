## Objective

Eliminate untyped `dict[str, Any]` responses and unhandled malformed-UUID `500` errors in `OrchestrationController` (`src/goe/listener/controllers/orchestration.py`), expose durable job queue inspection endpoints (`GET /api/orchestration/jobs/` and `GET /api/orchestration/jobs/{execution_id}/`) reusing existing `JobStoreProtocol.list_jobs` and `JobStoreProtocol.get_job_by_execution_id`, register `goe://executions*` and `goe://jobs*` resources on `GOEResourcesController`, add an `MCPResourceLink` execution-log pointer tool on `/executions/{execution_id:str}/execution-log/link/`, and wire handler-level `ConfirmationGate.require_mcp_confirmation(...)` into `POST /api/orchestration/offload/` (`execute_offload`) while preserving direct HTTP REST `schemas.CommandScheduled` responses.

## Context

- `OrchestrationController.get_command_execution` currently returns `dict[str, Any]` and calls `ExecutionId.from_str(execution_id)` without catching `ValueError`, turning invalid UUID path parameters into HTTP `500` errors.
- Live log route path on `090941a` is `GET /api/orchestration/executions/{execution_id:str}/execution-log/` (`get_command_execution_log`), and `POST /api/orchestration/offload/` (`execute_offload_command`) returns `schemas.CommandScheduled(execution_id=..., status="QUEUED")`.
- `JobStoreProtocol` (`src/goe/listener/jobs/store.py`) already implements `list_jobs(self, *, limit: int = 100, status: JobState | None = None) -> list[JobRecord]` and `get_job_by_execution_id(self, execution_id: str) -> JobRecord | None` backed by `sqlite_list_jobs`/`oracle_list_jobs` and `sqlite_get_job`/`oracle_get_job` — reuse them directly without duplicating store methods or SQL queries. Note: in unit tests overriding `job_store`, patch `goe.listener.app._default_job_store` (or pass `dependencies={"job_store": Provide(..., sync_to_thread=False)}`) rather than patching `get_job_store` with `MagicMock` (`*args` breaks Litestar's `ParsedSignature.from_fn`).
- Direct HTTP REST callers (`get_mcp_request_context()` raising `RuntimeError`) must continue receiving `schemas.CommandScheduled` directly with zero confirmation token requirement and zero `MCPToolResult` wrapper so existing REST endpoints, `/schema/openapi.json`, and unit tests in `tests/unit/listener/test_orchestration_controllers.py` remain 100% compatible.
- Strategy justification (`behavior_tdd`): typed `CommandExecution` serialization, `400` UUID validation, job queue inspection routes, `MCPResourceLink` log pointers, and MCP-only MRTR/HMAC confirmation gating on `execute_offload` are observable API/MCP behaviors tested red-first in canonical `tests/unit/listener/test_orchestration_controllers.py`.

## Steps

1. Add failing behavioral tests in `tests/unit/listener/test_orchestration_controllers.py` covering:
   - `GET /api/orchestration/executions/{execution_id}/` returns typed `schemas.CommandExecution` (`200`), `404` when absent, and `400` (`ApplicationError`) when `execution_id` is not a valid UUID (same `400` check on `/executions/{execution_id}/execution-log/`).
   - `GET /api/orchestration/jobs/` (optional `status` validated against `JobState` returning `400` on invalid enum value, bounded `limit`) and `GET /api/orchestration/jobs/{execution_id}/` return typed `JobListResponse` and `JobStatusResponse` backed by `SqliteJobStore` (`404` when `execution_id` is unknown).
   - Simultaneous MCP discovery and reads over `POST /mcp`: `tools/list` exposes `get_command_executions`, `get_command_execution`, `get_command_execution_log`, `get_execution_log_link`, `list_offload_jobs`, `get_offload_job`, and `execute_offload` (with `annotations`), AND `resources/list` + `resources/templates/list` + `resources/read` resolve `goe://executions`, `goe://executions/{execution_id}`, `goe://executions/{execution_id}/log`, `goe://jobs`, and `goe://jobs/{execution_id}`.
   - `tools/call` on `get_execution_log_link` returns a `resource_link` content block pointing to `goe://executions/{execution_id}/log`.
   - `POST /api/orchestration/offload/` (`execute_offload`):
     - Direct HTTP REST `POST` with `execute=True` enqueues the job (`201` `schemas.CommandScheduled`) without requiring a confirmation token and without wrapping in `MCPToolResult`, and `GET /schema/openapi.json` returns `200` with the `CommandScheduled` response schema intact.
     - MCP `tools/call` (`task_input_before_start=True`) with `execute=True` and no confirmation returns `MCPInputRequiredResult` (`input_required` with `input_requests={"confirm": {...}, "confirmation_token": {...}}` and `request_state`) synchronously without enqueueing a job.
     - MCP `tools/call` with `execute=True` and either a valid `confirmation_token` or Round 2 `requestState` + `inputResponses={"confirm": True}` enqueues the job and returns `MCPToolResult` containing `structured_content` (`schemas.CommandScheduled`) plus `MCPResourceLink` (`goe://jobs/{execution_id}` and `goe://executions/{execution_id}/log`).
     - MCP `tools/call` with `execute=False` bypasses destructive confirmation gating.
2. Update `src/goe/listener/schemas.py`:
   - Add `JobStatusResponse(FrozenBaseStruct, frozen=True)` (with `@classmethod def from_record(cls, record: JobRecord) -> JobStatusResponse`) and `JobListResponse(FrozenBaseStruct, frozen=True)` (`count: int`, `results: list[JobStatusResponse]`), plus `log_resource_uri: str | None = None` on `CommandExecutionLog`.
3. Update `OrchestrationController` (`src/goe/listener/controllers/orchestration.py`) and `GOEResourcesController` (`src/goe/listener/controllers/resources.py`):
   - Add private helper `_parse_execution_id(raw_id: str) -> ExecutionId` (placed strictly below all public methods) translating `ValueError` into `exceptions.ApplicationError(status_code=400, message=f"Invalid execution_id UUID: {raw_id}")`.
   - Change `get_command_execution` return annotation to `schemas.CommandExecution` using `schemas.CommandExecution.from_item(...)`, and populate `log_resource_uri=f"goe://executions/{execution_identifier.as_str()}/log"` in `get_command_execution_log` (`GET /executions/{execution_id:str}/execution-log/`).
   - Add `GET /executions/{execution_id:str}/execution-log/link/` (`get_execution_log_link`) decorated with `@mcp_tool(name="get_execution_log_link", annotations=READ_ONLY_TOOL_ANNOTATIONS, ...)` returning `MCPResourceLink(name=f"execution-{execution_identifier.as_str()}.log", uri=f"goe://executions/{execution_identifier.as_str()}/log", mime_type="application/json")`.
   - Add `GET /jobs/` (`list_offload_jobs`, `@mcp_tool(name="list_offload_jobs", annotations=READ_ONLY_TOOL_ANNOTATIONS, ...)`) and `GET /jobs/{execution_id:str}/` (`get_offload_job`, `@mcp_tool(name="get_offload_job", annotations=READ_ONLY_TOOL_ANNOTATIONS, ...)`) delegating via `asyncio.to_thread` to `job_store.list_jobs(limit=..., status=...)` and `job_store.get_job_by_execution_id(execution_id)`.
   - Register static resources `goe://executions` and `goe://jobs` (with `@get("/...")` stacked above `@mcp_resource(uri="goe://...", ...)`) and templated `@get("/...", mcp_resource=..., mcp_resource_template="goe://...")` handlers for `goe://executions/{execution_id}`, `goe://executions/{execution_id}/log`, and `goe://jobs/{execution_id}` on `GOEResourcesController`.
   - Decorate `execute_offload_command` (`POST /offload/`) with `@mcp_tool(name="execute_offload", annotations=DESTRUCTIVE_TOOL_ANNOTATIONS, task_support="optional", task_input_before_start=True, ...)`, keep module top-level imports for `Request` and `ConfirmationGate` with zero inline `#` comments, retain return annotation `-> schemas.CommandScheduled` (using `typing.cast("schemas.CommandScheduled", ...)` on the MCP-only `MCPInputRequiredResult | MCPToolResult` return branch so `/schema/openapi.json`, `mypy`, and `@mcp_tool` `outputSchema` stay bound to `schemas.CommandScheduled`), check `try: ctx = get_mcp_request_context() except RuntimeError: ctx = None`, return `schemas.CommandScheduled` directly when `ctx is None`, and enforce `confirmation_gate.require_mcp_confirmation(...)` when `ctx is not None`.
