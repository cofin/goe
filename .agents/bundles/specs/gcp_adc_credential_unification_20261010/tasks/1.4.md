# Task 1.4: Update `offload.env` templates and `docs/gcp_setup.md` for keyless ADC

## Objective
Remove static JSON key file instructions from `templates/conf/offload.env.template.bigquery`, `templates/conf/offload.env.template.snowflake`, and `docs/gcp_setup.md`, and replace them with keyless Application Default Credentials (ADC), `GOOGLE_IMPERSONATE_SERVICE_ACCOUNT`, `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_QUOTA_PROJECT`, and Workload Identity Federation documentation.

## Context
- `templates/conf/offload.env.template.bigquery:8-9` and `templates/conf/offload.env.template.snowflake:50-51` advertise `# GOOGLE_APPLICATION_CREDENTIALS=` as `"Path to Google service account private key JSON file"`.
- `templates/conf/offload.env.template.bigquery:40-41` describes `GOOGLE_DATAPROC_SERVICE_ACCOUNT` without distinguishing serverless batch runtime identity from caller control-plane impersonation.
- `docs/gcp_setup.md:17-34` instructs operators to run `gcloud auth activate-service-account ... --key-file=/path/to/service-account-key.json`.
- `docs/gcp_setup.md:85-92` grants `roles/iam.serviceAccountUser` project-wide instead of scoping `serviceAccountUser` to the Dataproc runtime SA and documenting `roles/iam.serviceAccountTokenCreator` for impersonation.
- `docs/gcp_setup.md:361` still invokes `$OFFLOAD_HOME/bin/offload` instead of `goe offload`.

## Steps

### Step 1: Update `templates/conf/offload.env.template.bigquery` and `templates/conf/offload.env.template.snowflake`
1. In `templates/conf/offload.env.template.bigquery:8-9`, replace the `GOOGLE_APPLICATION_CREDENTIALS` comment block with:
```bash
# Google Cloud authentication uses Application Default Credentials (ADC).
# Static service account private key JSON files are deprecated and not required.
# Default GCP project for BigQuery jobs and Cloud Storage client operations:
GOOGLE_CLOUD_PROJECT=
# Optional quota/billing project for user or impersonated ADC credentials:
GOOGLE_CLOUD_QUOTA_PROJECT=
# Optional target service account email for GOE to impersonate (requires roles/iam.serviceAccountTokenCreator):
GOOGLE_IMPERSONATE_SERVICE_ACCOUNT=
```
2. In `templates/conf/offload.env.template.bigquery:39-44`, clarify `GOOGLE_DATAPROC_SERVICE_ACCOUNT` and add `GOOGLE_DATAPROC_IMPERSONATE_SERVICE_ACCOUNT`:
```bash
# Runtime worker service account for Dataproc Serverless batches (--service-account):
GOOGLE_DATAPROC_SERVICE_ACCOUNT=
# Optional caller service account to impersonate when submitting Dataproc jobs/batches (defaults to GOOGLE_IMPERSONATE_SERVICE_ACCOUNT):
# GOOGLE_DATAPROC_IMPERSONATE_SERVICE_ACCOUNT=
```
3. In `templates/conf/offload.env.template.snowflake:50-51`, replace `#GOOGLE_APPLICATION_CREDENTIALS=` with the same `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_QUOTA_PROJECT`, and `GOOGLE_IMPERSONATE_SERVICE_ACCOUNT` block for GCS staging.

### Step 2: Update `docs/gcp_setup.md`
1. Replace `docs/gcp_setup.md:17-34` (`gcloud auth activate-service-account --key-file=...`) with a comprehensive **Authentication (Keyless ADC & Service Account Impersonation)** section covering:
   - Attached Service Account on GCE, GKE Workload Identity, or Cloud Run (recommended in-cloud default).
   - Local development and operator CLI via `gcloud auth application-default login` + `GOOGLE_IMPERSONATE_SERVICE_ACCOUNT=<sa-email>`.
   - On-premises / CI environments via Workload Identity Federation (`external_account` credential config files).
2. In `docs/gcp_setup.md:85-92`, scope `roles/iam.serviceAccountUser` to the Dataproc runtime service account and document granting `roles/iam.serviceAccountTokenCreator` on the GOE service account to human/CI principals that impersonate it.
3. In `docs/gcp_setup.md:279-282`, update `spark.hadoop.fs.gs.auth.type=APPLICATION_DEFAULT` and `spark.hadoop.fs.gs.auth.impersonation.service.account` guidance for `gcs-connector` 3.0.x.
4. In `docs/gcp_setup.md:361`, replace `$OFFLOAD_HOME/bin/offload` with `goe offload`.
