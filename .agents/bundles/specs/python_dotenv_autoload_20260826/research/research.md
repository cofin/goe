# GOE Installation Lifecycle & python-dotenv Auto-loading Feasibility

## Executive Summary

This research investigates the end-to-end installation, build, packaging, and configuration lifecycle of the Gluent Offload Engine (`GOE`) codebase, specifically evaluating the feasibility, mechanics, and design recommendations for automatically loading `offload.env` via `python-dotenv`.

### Key Findings
1. **`python-dotenv` is already a core dependency**: `python-dotenv` is listed in [pyproject.toml:63](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/pyproject.toml#L63) (resolved to v1.2.3 in `uv.lock`) and wrapped in [`src/goe/config/config_file.py:load_env`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/config/config_file.py#L39-L50).
2. **Current Loading is Fragmented and Latent**: `load_env()` is currently only invoked during [`OrchestrationConfig.from_dict()`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/config/orchestration_config.py#L333), [`connect()`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/connect/connect.py#L478), and [`agg_validate.py`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/scripts/agg_validate.py#L273). As a result:
   - CLI commands ([`goe offload`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/cli/commands/offload.py#L136-L158), `goe sync`, `goe validate`) evaluate option default values via `orchestration_defaults.*_default()` *before* `OrchestrationConfig.from_dict()` is reached, leading to missing defaults if not already exported into the shell environment.
   - Module-level constants (e.g. [`DEFAULT_REPORT_DIRECTORY`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/offload/offload_status_report.py#L85) and listener app settings) bind unconfigured fallbacks at import time.
3. **Full Compatibility with `offload.env` Syntax**: `python-dotenv` supports POSIX parameter expansion (`interpolate=True`), comments (`#`), optional `export ` prefixes, and single/double quoted values (including JSON configuration blocks like `OFFLOAD_TRANSPORT_SPARK_PROPERTIES`).
4. **Auto-Loading is Completely Feasible**: By implementing multi-stage path discovery in [`config_file.py`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/config/config_file.py) and triggering `load_env()` during top-level initialization ([`src/goe/__init__.py`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/__init__.py) and [`src/goe/cli/main.py`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/src/goe/cli/main.py)), `offload.env` can be seamlessly loaded without requiring manual `source` commands or shell wrappers.

## 2. Deep Dive: `offload.env` and `OFFLOAD_HOME`

### 2.1 Role and Structure of `offload.env`
`offload.env` defines essential environment variables across all GOE operations:
- **Frontend RDBMS**: `FRONTEND_DISTRIBUTION`, `ORA_CONN`, `ORA_ADM_USER`, `ORA_APP_USER`, `ORACLEDB_THICK_MODE`.
- **Backend DW / Storage**: `BACKEND_DISTRIBUTION`, `QUERY_ENGINE`, `BIGQUERY_DATASET_PROJECT`, `OFFLOAD_FS_CONTAINER`, `OFFLOAD_FS_SCHEME`.
- **Transport & Spark**: `OFFLOAD_TRANSPORT`, `OFFLOAD_TRANSPORT_USER`, `OFFLOAD_TRANSPORT_CMD_HOST`, `OFFLOAD_TRANSPORT_SPARK_PROPERTIES`.
- **Paths & Logging**: `OFFLOAD_LOGDIR`, `PASSWORD_KEY_FILE`.

### 2.2 Sourcing Mechanics & The "Shell Sourcing" Myth
In [`tools/goe-shell-functions.sh:83-88`](file:///usr/local/google/home/codyfincher/code/gluent/next-goe/tools/goe-shell-functions.sh#L83-L88):
```bash
function source_goe_env {
    if [[ ! -f "$1/conf/offload.env" ]]; then
        raise_and_exit ${FUNCNAME[0]} 2 "File does not exist: $1/conf/offload.env"
    fi
    export OFFLOAD_HOME=$1
}
```
**Observation**: Despite its name, `source_goe_env` does **not** source `offload.env` into shell variables—it only asserts file existence and exports `OFFLOAD_HOME`. All actual key-value loading into process memory has always been delegated to Python.

## 3. Feasibility of `python-dotenv` Auto-Loading

### 3.1 Syntax and Feature Compatibility
`python-dotenv` (v1.2.3) natively supports:
- **POSIX Variable Expansion**: Constructs like `OFFLOAD_TRANSPORT_USER=${USER}` and `ORACLEDB_THICK_MODE=${USE_ORACLE_WALLET}` expand automatically when `interpolate=True` (default in `load_dotenv`).
- **Quotes & JSON Literals**: Values like `OFFLOAD_TRANSPORT_SPARK_PROPERTIES='{"spark.extraListeners": "GOETaskListener"}'` parse cleanly without altering interior quotation.
- **Prefixes & Comments**: `export KEY=val` and `# Comment` lines are handled transparently.
- **Precedence Preservation**: `load_dotenv` uses `override=False` by default, guaranteeing that environment variables explicitly set in container runtime, CI, or shell take precedence over `offload.env`.

### 3.2 Evaluation of Auto-Loading Mechanisms

| Mechanism | Description | Pros | Cons | Recommendation |
| :--- | :--- | :--- | :--- | :--- |
| **Option A: Top-level `goe/__init__.py`** | Load automatically upon `import goe` | Works for CLI, listener, scripts, and direct library imports. | Could affect unit tests if not guarded with test detection/env flag. | **Recommended (with test guard)** |
| **Option B: `sitecustomize.py` / `.pth`** | Inject into Python environment | Runs before any script executes. | Fragile, non-standard, wheel-incompatible, breaks on editable `uv` installs. | **Reject** |
| **Option C: CLI-only Pre-Run Hook** | Hook in `goe.cli.main` | Isolates loading to CLI. | Misses ASGI servers (`goe.listener.asgi`), background workers, and direct imports. Runs after some module imports. | **Reject as sole mechanism** |
| **Option D: Multi-Stage Path Discovery** | Enhance `get_environment_file_path()` | Discovers `offload.env` without needing `$OFFLOAD_HOME` to be pre-exported. | None. | **Recommended** |

## 4. Proposed Solution & Architecture

### 4.1 Enhanced Discovery in `src/goe/config/config_file.py`
Upgrade `get_environment_file_path()` to search candidate paths in prioritized order:
1. `os.environ.get("GOE_CONFIG_FILE")` or `os.environ.get("OFFLOAD_ENV_FILE")` (explicit override).
2. `os.path.join(os.environ["OFFLOAD_HOME"], "conf", CONFIG_FILE_NAME)` (if `$OFFLOAD_HOME` is set).
3. Search upward from current working directory for `conf/offload.env` or `offload.env` via `dotenv.find_dotenv()`.
4. Standard system deployment paths: `/opt/goe/offload/conf/offload.env` and `/u01/app/goe/offload/conf/offload.env`.

If an `offload.env` file is discovered and `OFFLOAD_HOME` is unset, `config_file.py` can automatically set `os.environ["OFFLOAD_HOME"]` to the parent directory of `conf/`.

```python
def find_environment_file() -> str | None:
    # 1. Explicit override
    if explicit := (os.environ.get("GOE_CONFIG_FILE") or os.environ.get("OFFLOAD_ENV_FILE")):
        if os.path.exists(explicit):
            return explicit

    # 2. Standard OFFLOAD_HOME/conf/offload.env
    if offload_home := os.environ.get("OFFLOAD_HOME"):
        candidate = os.path.join(offload_home, "conf", CONFIG_FILE_NAME)
        if os.path.exists(candidate):
            return candidate

    # 3. Dynamic search in working directory hierarchy
    if found := (find_dotenv(f"conf/{CONFIG_FILE_NAME}") or find_dotenv(CONFIG_FILE_NAME)):
        return found

    # 4. Standard default system paths
    for default_home in ["/opt/goe/offload", "/u01/app/goe/offload"]:
        candidate = os.path.join(default_home, "conf", CONFIG_FILE_NAME)
        if os.path.exists(candidate):
            return candidate

    return None
```

### 4.2 Auto-Loading with Test Isolation Guard
In `src/goe/__init__.py` and `src/goe/cli/main.py`:
```python
def _autoload_environment() -> None:
    if os.environ.get("GOE_NO_AUTOLOAD_ENV") or "PYTEST_CURRENT_TEST" in os.environ:
        return
    from goe.config.config_file import load_env
    load_env()

_autoload_environment()
```

### 4.3 Benefits
- **Zero Shell Sourcing Required**: Users can execute `goe offload ...` directly without having to run `source /path/to/offload.env` or `source_goe_env`.
- **Consistent CLI Defaults**: `rich-click` command defaults resolve with active environment parameters populated.
- **Preserved Test Isolation**: Unit tests running in `pytest` with mock environments remain unaffected.
- **Container & VM Parity**: Identical execution model across local `.venv`, Cloud Run, and on-prem VMs.
