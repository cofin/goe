# Task 4.1: Update documentation and knowledge base patterns for environment auto-discovery

## Objective
Document the modernized configuration loading behavior, environment variable precedence, and override controls (`GOE_CONFIG_FILE`, `OFFLOAD_ENV_FILE`, `GOE_NO_AUTOLOAD_ENV`) across public documentation, developer guides, and Flow knowledge base patterns.

## Context
Clear documentation ensures that both human operators and AI agents understand how `offload.env` is discovered, how to override configuration in automated pipelines, and how test runners maintain isolation.

## Steps
1. Update `README.md` and `docs/user_guide.md` explaining that GOE automatically discovers `conf/offload.env` or `offload.env` without requiring manual `source` commands.
2. Document environment override options:
   - `GOE_CONFIG_FILE` / `OFFLOAD_ENV_FILE`: Point to an explicit configuration file path.
   - `GOE_NO_AUTOLOAD_ENV=1`: Disable automatic loading (useful in strictly controlled CI environments).
3. Update `AGENTS.md` and `.agents/bundles/knowledge/patterns.md` documenting the durable environment resolution patterns.
4. Run static validation and lint checks across the repository.

## Verification
- Verify formatting with `uv run ruff format --check .` and `uv run ruff check .`.
- Run `make test-unit`.

## Acceptance Criteria
- [ ] Documentation accurately reflects multi-stage discovery and auto-loading behavior.
- [ ] Durable configuration patterns captured in knowledge bundles.
- [ ] Full unit test suite passes cleanly.
