# Task 1.4: Optimize GCP transport selection order, modernize Query Import, and add optional `BigQueryStorageWriteStreamer`

## Objective

Optimize `choose_offload_transport_method` (`src/goe/offload/offload_transport.py:553-598`) so `BACKEND_DISTRO_GCP` evaluates `QUERY_IMPORT` -> `SPARK_DATAPROC_GCLOUD` -> `SPARK_BATCHES_GCLOUD` -> `SPARK_SUBMIT` without running Sqoop/Livy/Thrift availability probes; modernize `OffloadTransportQueryImport` (`src/goe/offload/offload_transport.py:2366-2508`) to delete the subprocess `rm -f` call in favor of `Path.unlink(missing_ok=True)` and raise the BigQuery `fetch_size` ceiling from `1000` to `10000`; and introduce an optional, capability-gated `BigQueryStorageWriteStreamer` (`src/goe/offload/bigquery/bigquery_storage_write.py`) that streams Arrow batches via `google.cloud.bigquery_storage_v1` when installed and falls back cleanly to GCS staging when absent.

## Context

1. **GCP Transport Selection Order (`src/goe/offload/offload_transport.py:553-598`):**
   - Currently, `choose_offload_transport_method` (`L553-598`) evaluates `OFFLOAD_TRANSPORT_GOE_METHODS` (`SPARK_THRIFT`, `QUERY_IMPORT`, `SPARK_LIVY`, `SPARK_SUBMIT`), then `OFFLOAD_TRANSPORT_SQOOP_METHODS` (`SQOOP`, `SQOOP_BY_QUERY`), and only then `OFFLOAD_TRANSPORT_GCP_METHODS` (`SPARK_DATAPROC_GCLOUD`, `SPARK_BATCHES_GCLOUD`).
   - On `BACKEND_DISTRO_GCP`, every large-table offload in `AUTO` mode wastes time probing Thrift, Livy, Spark Submit, and Sqoop before selecting Dataproc.
   - When `config.backend_distribution == BACKEND_DISTRO_GCP` and `config.offload_transport == OFFLOAD_TRANSPORT_AUTO`, the candidate sequence should be:
     `[OFFLOAD_TRANSPORT_METHOD_QUERY_IMPORT, OFFLOAD_TRANSPORT_METHOD_SPARK_DATAPROC_GCLOUD, OFFLOAD_TRANSPORT_METHOD_SPARK_BATCHES_GCLOUD, OFFLOAD_TRANSPORT_METHOD_SPARK_SUBMIT]`, skipping Sqoop, Thrift, and Livy entirely.
2. **Query Import Modernization & Dead-Code Removal (`src/goe/offload/offload_transport.py:2366-2508`):**
   - In `OffloadTransportQueryImport.__init__` (`L2388-2390`), `self._rdbms_fetch_size = min(offload_operation.offload_transport_fetch_size, 1000)` caps the Oracle array fetch size at `1000` (a legacy Hadoop-era constraint). When `self._target == DBTYPE_BIGQUERY`, raise this ceiling to `10000` (`QUERY_IMPORT_BIGQUERY_MAX_FETCH_SIZE = 10000`).
   - In `_query_import_copy_to_dfs` (`L2478-2484`), delete `self._run_os_cmd(["rm", "-f", local_data_path], optional=True)` and replace it with `Path(local_data_path).unlink(missing_ok=True)` inside a `try ... finally` block so local files are never orphaned even if `copy_from_local` raises.
3. **Optional BigQuery Storage Write API Streamer (`src/goe/offload/bigquery/bigquery_storage_write.py`):**
   - `google-cloud-bigquery-storage` is an optional dependency (`pyproject.toml` `[project.optional-dependencies]`).
   - `BigQueryStorageWriteStreamer` checks at runtime whether `google.cloud.bigquery_storage_v1` and `pyarrow` are importable (`is_bigquery_storage_write_available()`). When enabled via `offload_transport_bigquery_storage_write=True` and available, it streams Arrow record batches (`AppendRowsRequest` with `ArrowRecordBatch` on the default/committed write stream) directly into the BigQuery staging table. When the package is not installed or the flag is disabled, `OffloadTransportQueryImport` seamlessly uses the standard GCS staging upload path.

```python
# SPDX-FileCopyrightText: 2026 The GOE Authors
# SPDX-License-Identifier: Apache-2.0

"""Optional BigQuery Storage Write API Arrow streamer for small-table Query Import."""

import importlib.util
from typing import Any

from goe.offload.offload_messages import VERBOSE_LEVEL, VVERBOSE_LEVEL

__all__ = [
    "BigQueryStorageWriteStreamer",
    "is_bigquery_storage_write_available",
]


def is_bigquery_storage_write_available() -> bool:
    """Return True if both google-cloud-bigquery-storage and pyarrow are installed."""
    try:
        bq_storage_spec = importlib.util.find_spec("google.cloud.bigquery_storage_v1")
        pyarrow_spec = importlib.util.find_spec("pyarrow")
        return bq_storage_spec is not None and pyarrow_spec is not None
    except (ImportError, ValueError, TypeError):
        return False


class BigQueryStorageWriteStreamer:
    """Stream PyArrow RecordBatches directly into a BigQuery staging table via Storage Write API."""

    def __init__(
        self,
        project_id: str,
        dataset_id: str,
        table_id: str,
        messages: Any,
        dry_run: bool = False,
    ) -> None:
        """Initialize the Storage Write streamer for a target BigQuery dataset and table."""
        self._project_id = project_id
        self._dataset_id = dataset_id
        self._table_id = table_id
        self._messages = messages
        self._dry_run = dry_run

    @property
    def table_resource_path(self) -> str:
        """Return the Storage Write API table resource path."""
        return f"projects/{self._project_id}/datasets/{self._dataset_id}/tables/{self._table_id}"

    def is_available(self) -> bool:
        """Return True if the Storage Write API client library is available."""
        return is_bigquery_storage_write_available()

    def append_arrow_batches(self, record_batches: list[Any], arrow_schema: Any) -> int:
        """Append a sequence of PyArrow RecordBatches to the default committed stream."""
        self._messages.log(
            f"BigQuery Storage Write API stream target: {self.table_resource_path}",
            detail=VERBOSE_LEVEL,
        )
        if self._dry_run or not record_batches:
            return 0

        from google.cloud import bigquery_storage_v1
        from google.cloud.bigquery_storage_v1 import types as bq_storage_types

        write_client = bigquery_storage_v1.BigQueryWriteClient()
        stream_name = f"{self.table_resource_path}/_default"
        serialized_schema = arrow_schema.serialize().to_pybytes()

        total_rows = 0
        requests = []
        for idx, batch in enumerate(record_batches):
            req = bq_storage_types.AppendRowsRequest()
            if idx == 0:
                req.write_stream = stream_name
                req.arrow_rows.writer_schema.serialized_schema = serialized_schema
            req.arrow_rows.rows.serialized_record_batch = batch.serialize().to_pybytes()
            requests.append(req)
            total_rows += batch.num_rows

        for response in write_client.append_rows(iter(requests)):
            if response.error.code != 0:
                raise RuntimeError(f"BigQuery Storage Write error: {response.error.message}")

        self._messages.log(
            f"BigQuery Storage Write appended {total_rows} rows to {self.table_resource_path}",
            detail=VVERBOSE_LEVEL,
        )
        return total_rows
```
