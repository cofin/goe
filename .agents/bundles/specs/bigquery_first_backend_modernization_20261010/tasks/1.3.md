# Task 1.3: Load staged files into native BigQuery load tables with external-table fallback

## Objective

When `bigquery_load_table_mode == "NATIVE"` (Task 1.1), `BackendBigQueryTable._create_load_table` loads `<staging location>/part*` into the load table with `Client.load_table_from_uri` (`WRITE_TRUNCATE`, GOE job labels, CMEK, Parquet `decimal_target_types`) instead of creating an external table, so `validate_type_conversions` and `load_final_table` read native storage. `EXTERNAL` keeps the existing external table path unchanged.

## Context

- Baseline `46890a8`. `src/goe/offload/bigquery/bigquery_backend_table.py`:
  - imports `L12-56` (`from goe.offload.offload_messages import VERBOSE, VVERBOSE` at `L34`); `__init__` (`L62-99`) sets `self._kms_key_name = self._db_api.kms_key_name()` (`L99`).
  - `_create_load_table(self, staging_file, with_terminator=False) -> list` (`L105-138`) builds `load_table_location = "%s/part*" % self.get_staging_table_location()` and calls `self._db_api.create_table(..., storage_format=staging_file.file_format, location=load_table_location, external=True, with_terminator=with_terminator)`.
  - `post_transport_tasks` (`L512-514`) calls the base `_recreate_load_table` (`backend_table.py:936-939`: `_drop_load_table()` then `_create_load_table(staging_file)`), so changing `_create_load_table` covers every transport.
  - `cleanup_staging_area` (`L405-407`) drops the load table and staged files for both modes.
- `BackendBigQueryApi` public helpers used: `bq_client()` (`bigquery_backend_api.py:728-730`), `bq_dataset_id(db_name)` (`L732-734`), `job_labels()` (added by Task 1.2).
- Schema: the load job does **not** pass an explicit schema. Avro and Parquet are self-describing; the external table also infers its schema from the files, so string-staged columns (DATE, TIMESTAMP, DECIMAL, `INTEGER_38`, intervals, per `parquet_staging_file.py:101-182`) stay `STRING` and `_staging_to_backend_cast` (`bigquery_backend_table.py:269-399`) SQL is unchanged. `decimal_target_types` only affects Parquet `DECIMAL` logical columns (none are produced today) and preserves NUMERIC/BIGNUMERIC precision if a future staging change emits them.
- `google-cloud-bigquery==3.44.0`: `LoadJobConfig(**properties)` accepts `source_format`, `write_disposition`, `labels`, `decimal_target_types`, `destination_encryption_configuration`; `bigquery.DecimalTargetType.{NUMERIC,BIGNUMERIC,STRING}`; `Client.load_table_from_uri(source_uris, destination, ..., job_config=...) -> LoadJob` with `.result()`, `.job_id`, `.output_rows`. Batch load jobs use the free shared slot pool (https://cloud.google.com/bigquery/pricing#data_ingestion_pricing).
- No base-class change: `BackendApiInterface`/`BackendTableInterface` and capability dicts are untouched.

```python
# SPDX-FileCopyrightText: 2026 The GOE Authors
# SPDX-License-Identifier: Apache-2.0

"""Native BigQuery load job configuration for GOE staged files."""

from google.cloud import bigquery

from goe.offload.offload_constants import FILE_STORAGE_FORMAT_AVRO, FILE_STORAGE_FORMAT_PARQUET

PARQUET_DECIMAL_TARGET_TYPES = [
    bigquery.DecimalTargetType.NUMERIC,
    bigquery.DecimalTargetType.BIGNUMERIC,
    bigquery.DecimalTargetType.STRING,
]
STAGING_SOURCE_FORMATS = {
    FILE_STORAGE_FORMAT_AVRO: bigquery.SourceFormat.AVRO,
    FILE_STORAGE_FORMAT_PARQUET: bigquery.SourceFormat.PARQUET,
}


def build_staging_load_job_config(
    staging_format: str, kms_key_name: str | None, labels: dict[str, str]
) -> bigquery.LoadJobConfig:
    """Return a WRITE_TRUNCATE load job config for GOE staged Avro or Parquet files.

    No explicit schema is set: the staged files are self-describing, matching the schema inference of the
    external table so string-staged columns remain STRING for validate_type_conversions.
    """
    if staging_format not in STAGING_SOURCE_FORMATS:
        raise ValueError(f"Unsupported BigQuery staging format: {staging_format}")
    job_config = bigquery.LoadJobConfig(
        source_format=STAGING_SOURCE_FORMATS[staging_format],
        write_disposition=bigquery.WriteDisposition.WRITE_TRUNCATE,
        labels=labels,
    )
    if staging_format == FILE_STORAGE_FORMAT_PARQUET:
        job_config.decimal_target_types = PARQUET_DECIMAL_TARGET_TYPES
    if kms_key_name:
        job_config.destination_encryption_configuration = bigquery.EncryptionConfiguration(kms_key_name=kms_key_name)
    return job_config
```

```python
    def _load_native_load_table(self, staging_file, load_table_location: str) -> list:
        """Load staged files into a native load table with a batch load job and return the logged command."""
        destination = f"{self._db_api.bq_dataset_id(self._load_db_name)}.{self._load_table_name}"
        job_config = build_staging_load_job_config(
            staging_file.file_format, self._kms_key_name, self._db_api.job_labels()
        )
        cmd = (
            f"BigQuery load job: {load_table_location} -> {destination} "
            f"(format={staging_file.file_format}, write_disposition=WRITE_TRUNCATE)"
        )
        self._log(cmd, detail=VERBOSE)
        if not self._dry_run:
            load_job = self._db_api.bq_client().load_table_from_uri(
                load_table_location, destination, job_config=job_config
            )
            load_job.result()
            self._log(f"BigQuery load job {load_job.job_id} loaded {load_job.output_rows} rows", detail=VVERBOSE)
        return [cmd]
```
