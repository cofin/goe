# Task 1.3: Refactor BackendBigQueryTable to select ingest strategies and preserve BigQuery golden characterization

## Objective

1. Refactor `src/goe/offload/bigquery/bigquery_backend_table.py` to delegate native load jobs, sub-threshold `< 10 MiB` direct Arrow uploads, and Storage Write API streams through `select_bigquery_ingest_strategy` and `self._db_api.execute_ingest(...)`, and add `ingest_direct_to_final_table(staging_file, arrow_source=None, payload_bytes=None)` for single-job direct target ingestion when staged-only preconditions (UDF partition functions, `--offload-chunk-column`, `--preserve-load-table`, or stringified staging casts) are absent.
2. Add unit tests in `tests/unit/offload/bigquery/test_bigquery_backend_table.py` verifying strategy selection across `BIGQUERY_LOAD_TABLE_MODE_NATIVE`, `EXTERNAL`, `< 10 MiB` Arrow streams, `>= 10 MiB` GCS Parquet loads, and `STORAGE_WRITE` mode, plus automatic fallback to staged load + `INSERT INTO ... SELECT` when UDF partition functions or `--offload-chunk-column` are configured.
3. Verify `tests/unit/characterization/test_offload_bigquery_golden.py` remains 100% green.

## Context

- `src/goe/offload/bigquery/bigquery_backend_table.py` (551 LOC at `d6a02fe`):
  - `_create_load_table` (`:244-281`) checks `self._orchestration_config.bigquery_load_table_mode == BIGQUERY_LOAD_TABLE_MODE_NATIVE` and calls `_load_native_load_table(staging_file, load_table_location)` (`:283-302`); otherwise it calls `self._db_api.create_table(..., external=True)`.
  - `_load_native_load_table` (`:283-302`) currently builds `LoadJobConfig` and calls `load_table_from_uri` directly. Delegating `_load_native_load_table` to `BigQueryLoadRequest` + `self._db_api.execute_ingest(request, strategy)` unifies native load table ingestion and direct target table ingestion under `BigQueryIngestStrategyProtocol` while emitting the exact command string pinned by `tests/unit/characterization/test_offload_bigquery_golden.py`.
  - Direct target ingestion eligibility (`can_ingest_direct_to_target(staging_file) -> bool`): returns `True` when:
    1. `staging_file.file_format == FILE_STORAGE_FORMAT_PARQUET`
    2. Neither `self._user_requested_offload_chunk_column` nor `getattr(self._orchestration_config, "preserve_load_table", False)` is set
    3. No partition column on the table uses a backend SQL UDF (`col.partition_info and col.partition_info.function`)
    4. Every column in `self.get_columns()` is already target-typed in the Parquet/Arrow stream (no SQL `PARSE_DATE` / `SAFE_CAST` string conversion required in `_staging_to_backend_cast`).
