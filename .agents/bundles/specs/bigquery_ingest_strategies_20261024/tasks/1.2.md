# Task 1.2: Refactor BackendBigQueryApi onto BackendCapabilities, CachedBackendCatalog, DialectSqlEngine, and BigQueryIngestStrategyProtocol

## Objective

1. Refactor `src/goe/offload/bigquery/bigquery_backend_api.py` to replace `self._cached_bq_tables` with `self.catalog` (`CachedBackendCatalog` from Chapter 9.2), use `BackendCapabilities.for_bigquery()`, delegate SQL generation (`create_table`, `create_external_table`, `alter_add_columns`, `properties_clause`) to `DialectSqlEngine("bigquery")` (from PRD 7), add `warm_schema(db_name)` to batch-load dataset metadata in two `INFORMATION_SCHEMA` queries, and expose `execute_ingest(request, strategy=None) -> BigQueryLoadResult`.
2. Update `src/goe/observability/bigquery.py` to record `stream_name` in `_JOB_ATTRIBUTES` and expose `record_bigquery_stream_metadata`.
3. Add unit tests in `tests/unit/offload/bigquery/test_bigquery_backend_api.py` covering catalog caching and invalidation across `create_table`, `drop_table`, `add_columns`, `alter_sort_columns`, `warm_schema`, and `execute_ingest`.

## Context

- `src/goe/offload/bigquery/bigquery_backend_api.py` (2,245 LOC at `d6a02fe`, with column type mapping methods already delegated to `CanonicalTypeRegistry` in Chapter 9.1 task 1.4):
  - Currently maintains a private `self._cached_bq_tables: dict[str, bigquery.Table] = {}` (`:168`, `:2009-2013`, `:2091-2100`) and calls `self._forget_bq_table(db_name, table_name)` on `add_columns` (`:212`), `alter_sort_columns` (`:230`), `create_table`, and `drop_table`.
  - Replacing `self._cached_bq_tables` with `self.catalog.get_native_handle(db_name, table_name, loader)` and `self.catalog.on_create_table` / `self.catalog.on_drop_table` / `self.catalog.on_alter_table` / `self.catalog.on_load_table` unifies SDK `bigquery.Table` caching and column/size/partition caching in `CachedBackendCatalog`.
  - `_forget_bq_table(db_name, table_name)` calls `self.catalog.invalidate_table(db_name, table_name)` so any internal call site or subclass hook invalidates the unified catalog.
  - `warm_schema(db_name)` executes two parameterized `INFORMATION_SCHEMA` queries against `` `{project}.{db_name}`.INFORMATION_SCHEMA.TABLE_STORAGE `` (or `TABLES`) and `` `{project}.{db_name}`.INFORMATION_SCHEMA.COLUMNS ``, constructs `BackendTableSnapshot` instances for every table in `db_name`, and populates `self.catalog.warm_schema(db_name, snapshots)`.
  - `execute_ingest(self, request: BigQueryLoadRequest, strategy: BigQueryIngestStrategyProtocol | None = None) -> BigQueryLoadResult` selects the strategy via `select_bigquery_ingest_strategy` when `strategy is None`, runs `strategy.execute(request, bq_client=self._client, log_fn=self._log)`, and triggers `self.catalog.on_load_table(request.dataset, request.table)`.
