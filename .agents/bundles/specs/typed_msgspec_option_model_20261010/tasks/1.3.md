# Task 1.3: Migrate Rich-Click CLI Commands & Deduplicate Listener OffloadOptions Schema

## Objective

Replace `from optparse import Values` across all 5 Rich-Click CLI command modules (`src/goe/cli/commands/offload.py`, `src/goe/cli/commands/connect.py`, `src/goe/cli/commands/report.py`, `src/goe/cli/commands/sync.py`, `src/goe/cli/commands/validate.py`) with direct construction of typed `msgspec.Struct` option models (`OffloadOperationOptions`, `ConnectOptions`, `StatusReportOptions`, `SchemaSyncOptions`, `AggValidateOptions`), delete any remaining `optparse` glue in `src/goe/util/option_mixin.py` or `src/goe/logmgr.py` / `src/goe/cli/commands/logmgr.py`, **delete the duplicate 96-field `OffloadOptions` body in `src/goe/listener/schemas.py`** by subclassing/aliasing `OffloadOperationOptions` from `src/goe/config/options.py`, and verify zero `optparse` imports or duplicate option schemas remain anywhere in `src/goe/`.

## Context

- Every CLI command module currently imports `from optparse import Values` at line 6 or 7 and calls the deleted `get_*_options()` `OptionParser` functions:
  - `src/goe/cli/commands/connect.py:6` and `lines 58-66` (`_build_connect_options`)
  - `src/goe/cli/commands/offload.py:6` and `lines 522-547` (`_build_offload_options`)
  - `src/goe/cli/commands/report.py:6` and `lines 67-80` (`_build_report_options`)
  - `src/goe/cli/commands/sync.py:7` and `lines 75-85` (`_build_sync_options`)
  - `src/goe/cli/commands/validate.py:7` and `lines 103-113` (`_build_validate_options`)
- `src/goe/cli/commands/*.py` use zero-type-loss lazy imports (`if TYPE_CHECKING:` + `_LAZY_IMPORTS` + `bind_lazy_imports(__name__, _LAZY_IMPORTS)` at command entry) so `goe --help` stays under 200ms. Importing `ConnectOptions`, `OffloadOperationOptions`, `StatusReportOptions`, `SchemaSyncOptions`, and `AggValidateOptions` via `_LAZY_IMPORTS` (and `if TYPE_CHECKING:`) preserves fast CLI startup while providing full static types.
- `src/goe/listener/schemas.py:160-303` defines a duplicate 96-field `OffloadOptions(BaseStruct)` class and a duplicate alias-mapping table in `to_params_dict()` (`lines 262-303`). By subclassing or aliasing `OffloadOperationOptions` from `goe.config.options`, we delete ~145 lines of duplicated field definitions and alias-mapping logic in `src/goe/listener/schemas.py` and establish a single source of truth across CLI, Listener, and Core.
- If `src/goe/util/option_mixin.py` or `src/goe/logmgr.py` exists in the workspace or contains any residual `optparse` glue, delete it outright and ensure `src/goe/cli/commands/logmgr.py` has zero `optparse` references. (Note: `src/goe/conductor/hybrid_view_service.py` and `src/goe/listener/services/hybrid_view.py` are deleted as dead code in PRD 1 Chapter 1.1 and are not part of this task.)

```python
# SPDX-FileCopyrightText: 2026 The GOE Authors
# SPDX-License-Identifier: Apache-2.0

from typing import TYPE_CHECKING, Any

if TYPE_CHECKING:
    from goe.config.options import OffloadOperationOptions


def _build_offload_options(operation_name: str, **kwargs: Any) -> "OffloadOperationOptions":
    """Build typed OffloadOperationOptions merging defaults with explicit CLI flags."""
    overrides: dict[str, Any] = {"operation_name": operation_name}
    for key, val in kwargs.items():
        if val is not None:
            overrides[key] = val
    options = OffloadOperationOptions.from_mapping(overrides)
    if getattr(options, "verify", None) is not None:
        options.Verify = options.verify
    return options
```
