# Task 1.4: Add the AST architecture boundary verifier and wire it into make lint

## Objective

1. Create `tools/verify_architecture.py` to scan Python source files with `ast` and `tokenize` and enforce six architectural invariants:
   - `raw-json`: zero `json.dumps`, `json.loads`, or `msgspec.json` calls outside `src/goe/serializers.py`.
   - `sqlglot-boundary`: zero `sqlglot` imports outside `src/goe/offload/sql_ast/`.
   - `oracledb-boundary`: zero `oracledb` imports outside `src/goe/persistence/oracle/` and `src/goe/offload/oracle/`.
   - `nested-import`: zero function-scoped `import` or `from ... import` statements outside documented circular/optional exemptions.
   - `member-ordering`: public functions and methods must precede private `_` helpers in every module and class.
   - `inline-comment`: zero `#` comments inside function or method bodies.
2. Generate `tools/architecture_baseline.toml` recording existing pre-migration violations so `uv run python tools/verify_architecture.py` fails immediately on any new violation in touched or new files and fails when a baseline entry becomes stale (ratchet-down contract).
3. Wire `uv run python tools/verify_architecture.py` into the `lint` target in `Makefile` and test all six rules in `tests/unit/tools/test_verify_architecture.py`.

## Context

- Later chapters in PRDs 5–10 progressively eliminate legacy violations and remove their entries from `tools/architecture_baseline.toml`.
- `tools/verify_architecture.py` must expose a pure `scan_paths(paths: Sequence[Path], *, repo_root: Path, baseline: BaselineConfig | None = None) -> list[ArchitectureViolation]` API so unit tests can validate synthetic Python snippets in `tmp_path` without spawning subprocesses, plus a `main(argv: Sequence[str] | None = None) -> int` CLI entry point that writes findings to `sys.stderr.write` and returns exit code `1` on unbaselined violations or stale baseline entries and `0` when clean.
- Python 3.12+ includes `tomllib` in the standard library for parsing `tools/architecture_baseline.toml`.
