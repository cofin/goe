# Task 1.3: Migrate `OracleQuery` and `OracleFrontendApi` Metadata SQL with Dead-Code Removal

## Objective

1. Refactor `src/goe/util/ora_query.py` (`L40-364`) to delegate query execution, parameter normalization, and row projection to `OracleGateway` while preserving 100% of Oracle thick/thin mode, Wallet/LDAP/TNS/EZConnect, `OracleQuery.fromcursor`, `OracleQuery.fromconnection`, and `output_type_handler` contracts, and deleting duplicated cursor row-zipping loops.
2. Externalize all 17 static Oracle data-dictionary queries in `src/goe/offload/oracle/oracle_frontend_api.py` (`L553-1054`) into `src/goe/offload/oracle/sql/frontend_metadata.sql` loaded via `SQLFileLoader`, **delete all 17 replaced inline SQL blocks and manual cursor row-zipping loops**, and keep clean exception handling in `_open_cursor` (`L619-630`) so reconnection on `ORA-02396` / `ORA-03113` / `ORA-03114` / `ORA-03135` (`#259`) occurs cleanly outside the `except oracledb.DatabaseError:` block while preserving 100% of Wallet/Proxy auth (`[%s]`), `MODULE`/`ACTION`/`TRACEFILE_IDENTIFIER` tracing, and PL/SQL refcursor/`OUT`-bind support.
   - Note: Oracle extraction row-source SQL (`AS OF SCN`, `PARTITION ("P1")`, `SUBPARTITION ("SP1")`) in `src/goe/offload/oracle/oracle_offload_transport_rdbms_api.py` is migrated in Chapter 3.2 (`sqlglot_ast_and_predicate_engine_20261010:1.2`) using the custom upstreamable `src/goe/offload/oracle/oracle_dialect.py` (`OracleExtractionQueryProtocol` / `OracleSqlEngine`).

## Context

- `src/goe/offload/oracle/oracle_frontend_api.py`:
  - `_connect` (`L163-198`) handles `existing_connection`, `use_oracle_wallet`, proxy authentication (`ora_adm_user[proxy_user]`), `ora_adm_user`/`ora_app_user`, sets `module = FRONTEND_TRACE_MODULE`, `action = self._trace_action`, `outputtypehandler = output_type_handler`, and calls `ping()`. All of these enterprise Oracle features must be preserved without regression.
  - `_open_cursor` (`L619-630`) catches `oracledb.DatabaseError` for sniped/disconnected sessions (`ORA-02396`, `ORA-03113`, `ORA-03114`, `ORA-03135`, issue `#259`) and reconnects via `self._connect()`. Capturing `should_reconnect = True` and calling `self._connect()` after exiting `except` keeps the exception context clean.
  - Data-dictionary queries in `_get_partition_column_names` (`L553-563`), `_instrumentation_snap` (`L580-583`), `_is_iot` (`L602-608`), `agg_validate_sample_column_names` (`L680-702`), `get_columns` (`L768-790`), `get_current_scn` (`L792-795`), `get_db_unique_name` (`L797-813`), `get_primary_key_column_names` (`L866-878`), `get_session_user` (`L888-891`), `get_table_default_parallelism` (`L904-907`), `get_table_size` (`L934-954`), `schema_exists` (`L1033-1036`), `table_exists` (`L1038-1041`), and `view_exists` (`L1050-1053`) are static queries with `:owner` / `:table_name` binds that belong in `src/goe/offload/oracle/sql/frontend_metadata.sql`.

### Step 2: Update `src/goe/offload/oracle/oracle_frontend_api.py` and `src/goe/util/ora_query.py` and Delete Inline SQL / Row-Zipping Loops

1. In `src/goe/offload/oracle/oracle_frontend_api.py`:
   - Add `get_oracle_frontend_sql_loader() -> SQLFileLoader` loading `src/goe/offload/oracle/sql/frontend_metadata.sql`.
   - Replace and **delete** the inline SQL string literals in all 16 metadata methods above, replacing them with `get_oracle_frontend_sql_loader().get_sql("<name>")`.
   - Delegate row dictionary/namedtuple projection in `_execute_query_fetch_x` (`L389-407`) to shared `OracleGateway` projection helpers, deleting duplicated `[col[0] for col in curs.description]` row-zipping loops while preserving `as_dict`, `as_named_tuple`, `fetch_action`, `cursor_fn`, `profile`, and `log_params`.
   - In `_open_cursor` (`L619-630`), keep clean exception handling by exiting the `except` block before calling `self._connect()`:

```python
# SPDX-FileCopyrightText: 2026 The GOE Authors
# SPDX-License-Identifier: Apache-2.0

should_reconnect = False
reconnect_message = ""
try:
    self._db_conn.ping()
except oracledb.DatabaseError as exc:
    (error,) = exc.args
    if error.code in (2396, 3113, 3114, 3135):
        should_reconnect = True
        reconnect_message = error.message
    else:
        raise

if should_reconnect:
    self._log(f"Reconnecting cursor after ping raised: {reconnect_message}", detail=VVERBOSE)
    self._connect()
```

2. In `src/goe/util/ora_query.py`:
   - Delegate row projection and named parameter execution to `OracleGateway` helpers while preserving `get_oracle_connection` (thick/thin client, DSN, wallet, SYSDBA/SYSOPER), `OracleQuery.fromcursor`, `OracleQuery.fromconnection`, and `output_type_handler` (`DB_TYPE_LONG` -> `DB_TYPE_LONG_STRING`, `DB_TYPE_LONG_RAW`).
