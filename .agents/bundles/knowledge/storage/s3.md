# Amazon AWS S3 Storage Adapter

<!-- truth: start -->
- `StagingStorageService` (`src/goe/filesystem/storage_service.py`) and `GOES3` (`src/goe/filesystem/goe_s3.py`) manage `s3://` and `s3a://` staging prefixes with 1,000-key batched `delete_objects` calls and `@traced_storage_call` spans.[^storage-svc][^goe-s3]
<!-- truth: end -->

AWS S3 staging storage is handled by `StagingStorageService` (`src/goe/filesystem/storage_service.py`) and `CloudStorageDfsAdapter` (`src/goe/filesystem/goe_dfs.py`), replacing the legacy `src/goe/filesystem/goe_s3.py` module.

## Key Features

- **Classes**: `StagingStorageService` and `CloudStorageDfsAdapter(GOEDfs)` (`backend_dfs="S3"`).
- **Driver / Library**: `boto3`, `botocore`, `sqlspec.storage`.
- **Scheme**: `s3://` or `s3a://<bucket>/<prefix>/<schema>/<table_name>/part*`.
- **Authentication**:
  1. AWS credential profile (`~/.aws/credentials`) or default `boto3.client("s3")` IAM chain (EC2 IAM Instance Profile / STS AssumeRole / environment variables).
- **Bounded `stat_uri` & Batch Deletion**:
  - `_s3_stat()` checks `head_object(Bucket=..., Key=...)` first and falls back to `list_objects_v2(Bucket=..., Prefix=..., MaxKeys=2)` to detect directory prefixes without unbounded pagination.
  - `_s3_delete()` batches keys into chunks of `DELETE_BATCH_LIMIT = 1000` per `delete_objects(Bucket=..., Delete={"Objects": batch})` call.
